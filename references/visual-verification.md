# 视觉验收细则

> 核心命题：**数字负责定位，眼睛负责验收。**
> 本文回答三个问题：怎么截、截哪里、怎么判断。

---

## 1. 分级：分的是"看哪种图"，不是"看不看"

| 级别 | 手段 | 成本 | 用途 |
|---|---|---|---|
| **L0** | 像素指纹 / 连通域数 / 平均亮度 / 直方图 | 最低 | **定位**用；验收时作量化补充 |
| **L1** | 单帧截图 + **亲眼看** | 低 | **验收默认手段** |
| **L2** | 连续截图 burst + 亲眼看关键帧 | 中 | 轻微动画时序 |
| **L3** | 录屏 / 帧序列回放 | 最高 | **仅"必须看动态才能判定"** |

**硬规则：**

- L1/L2 能判定的，**禁止**升级到 L3。
- L3 一次性产出帧序列 + 一个可拖动/慢放的回放页，**不要逐帧读进对话**。
- 判断"几何崩坏"用连通域数量**辅助**（正常 1~3，崩坏几十上百），**但仍需看图确认**。

## 2. 怎么截：抓真实画面的三个坑

### 坑 1：`preserveDrawingBuffer: false` 时截屏拿到空帧

浏览器的截图接口在渲染循环之外取缓冲区，此时缓冲已经被清空 → 抓到纯黑或纯白。

**正确做法（三选一）：**

```js
// A. 同一次 JS 调用里同步渲染 + 导出（最可靠）
renderer.render(scene, camera);
const url = canvas.toDataURL('image/png');

// B. 创建 renderer 时开 preserveDrawingBuffer
new THREE.WebGLRenderer({ canvas, preserveDrawingBuffer: true, antialias: true });

// C. 用本 skill 的接收端抓帧
//    python scripts/capture_frame.py --out-dir shots --port 8765
//    见下面第 3 节
```

### 坑 2：抓错 canvas

页面里有多个 canvas 时，用 `document.getElementById('<id>')` 精确定位，
**不要**用 `querySelector('canvas')`（拿到的是第一个，不一定是 3D 那个）。

### 坑 3：截到半成品

场景对象、贴图、合成器没就绪就截图 → 拍到空场景或缺材质。
截图前必须等场景真的 ready（用 `waitForFunction` 轮询就绪标志，不要死等固定秒数）。

## 3. 用本 skill 的 `capture_frame.py` 抓真实帧

它是一个本地 HTTP 接收端：页面里的 JS 把 canvas 的 dataURL POST 给它，它落盘成 PNG。

```
# 终端 A：起接收端
python scripts/capture_frame.py --out-dir shots --port 8765

# 终端 B：在页面控制台（或注入脚本）里
fetch('http://127.0.0.1:8765/shot?name=frame01', {
  method: 'POST',
  body: JSON.stringify({ dataUrl: canvas.toDataURL('image/png') })
});
```

要点：

- 跨域：接收端默认发 `Access-Control-Allow-Origin: *`。
- 落盘文件名 = `--out-dir` + `name` 参数 + `.png`。
- `--port` 默认 `8765`，被占用时脚本会自己找下一个空闲端口并打印实际端口。
- 抓完先看文件大小：`< 5 KB` 基本就是空帧。

## 4. 截哪里：看图清单

不要"扫一眼"。按任务类型逐条确认：

| 任务类型 | 眼睛必须确认的点 |
|---|---|
| **光影 / 阴影** | 家具底部有接触阴影？墙角有渐变暗部？阴影方向一致？过重 / 过轻？ |
| **材质 / 贴图** | 纹理花纹对得上？没糊 / 没拉伸 / 没黑块？木纹深浅有区分？ |
| **建模 / 几何** | 缺面？穿模？比例失真？碎片破面？朝向反了？ |
| **配色 / 调色** | 没偏色 / 发灰 / 过曝 / 死黑？该白的地方白、该暖的地方暖？ |
| **布局 / UI** | 不重叠 / 不溢出 / 不遮挡？字号清晰？ |
| **动画时序** | 起步是否自然？缓动有没有过冲？结束态是否完全到位？ |

**"看起来差不多"不算通过。** 交差时要能说出**具体哪里对、哪里还不对**。

## 5. 关键区域裁切放大

小图上看不清接触阴影、边缘锯齿、贴图接缝。必须裁切放大 2~4 倍再看。

```
python scripts/crop_compare.py --left before.png --right after.png \
    --region 30,40,70,80 --scale 3 --out ab.png
```

要点：

- **必须同一裁切区域**（像素级对齐），否则对比无意义。
- 放大用 LANCZOS，保持清晰。
- 只裁切放大（不带对比）：

```
python scripts/crop_compare.py --left before.png --out crop.png \
    --region 30,40,70,80 --scale 3
```

---

## 6. A/B 并排对比

改一个开关 / 参数后，**不要只看新图**。新旧两张同一区域裁切后并排放大，才能看清"到底出没出来"。

```
python scripts/crop_compare.py --left before.png --right after.png \
    --region 0,0,100,100 --scale 2 --out ab.png --sep magenta
```

输出布局：

```
┌────────────┬────────────┤
│  修复前     │  修复后     │   ← 中间洋红分隔线，防止看串
└────────────┴────────────┘
```

**A/B 看不出差异 → 说明改动根本没生效**，不要继续往下调参数。
回去查"改动是否被别的逻辑覆盖"（真实案例：运行时改 `castShadow` 后每 500ms 被补丁改回 `false`，
A/B 无差异才暴露了这点）。

A/B 适合**开关型**对比：AO 开/关、阴影 开/关、贴图 有/无。

## 7. 数值指标的正确用法

数值**不能替代**眼睛，但可以**辅助**回答"变化是多是少"：

- ✅ 适合：帧时间、首屏字节数、draw call 数、内存占用、连通域数量（几何崩坏）。
- ❌ 不适合：判断光影是否自然、材质是否好看、构图是否协调。

**指标达标 ≠ 视觉合格。** 指标只能排除"明显没变化"，排除不了"变化是错的"。

## 8. 交付前自检清单

```
[ ] 渲染出了真实画面（不是空白帧 / 不是半成品）
[ ] 图片已 Read 进上下文并实际看过
[ ] 按第 4 节清单逐条确认过
[ ] 关键区域裁切放大看过
[ ] A/B 对比用了同一裁切区域、放大后并排看过
[ ] 汇报第一句说的是"我看图确认了什么"
[ ] 数字只作量化补充
```

没做到第 1、2 条，就**不能**说"验收通过"。
